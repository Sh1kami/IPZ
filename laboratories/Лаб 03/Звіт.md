# Лабораторна робота 3

Панчишкін Богдан Олександрович, група 3ПРс/3.


## Тема роботи

Нефункціональне тестування


## Мета роботи

Оцінити продуктивність навчального сервісу за допомогою JMeter, зібрати метрики часу відповіді, помилок і пропускної здатності.


## Завдання

Підготувати навантажувальний сценарій, задати кількість користувачів і критерії прийняття, виконати вимірювання, проаналізувати результати та сформувати звіт.


## Теоретичні відомості

Нефункціональні перевірки оцінюють властивості системи. Навантажувальний тест показує поведінку за заданого потоку запитів; стрес-тест шукає межу стійкості; тривалий тест перевіряє деградацію з часом. У цій роботі вимірюється короткий локальний профіль HTTP-навантаження.

Середній час описує типовий запит, p95 показує межу для 95% спостережень, а throughput - кількість запитів за секунду. Відсоток помилок потрібно аналізувати разом зі швидкістю: швидка помилкова відповідь не є успішним обслуговуванням.

JMeter працює без GUI, моделює паралельні потоки й зберігає кожне спостереження в JTL. Response Assertion перевіряє код 200; HTML Dashboard формує агреговані таблиці та графіки.


## Хід виконання

План load/catalog.jmx містить три GET-запити: /api/health, /api/jobs і /api/jobs?query=Java. Для кожного запиту встановлено перевірку HTTP 200, connect timeout 3 с та response timeout 5 с.

Виконано три окремі прогони з 1, 5 і 15 користувачами, ramp-up 1 с та 20 ітераціями. Один користувач виконує 60 запитів. Разом отримано 60 + 300 + 900 = 1260 спостережень.

До запуску задано критерії: 0 HTTP-помилок і p95 не більше 500 мс. Тести виконувалися в локальній Docker-мережі на одному комп’ютері. Значення JTL агреговано скриптом; збережено також штатний JMeter Dashboard.


```text
jmeter -n -t load/catalog.jmx -Jusers=15 -Jloops=20 \
  -l evidence/load/users-15.jtl -e -o evidence/load/html-15
```


## Результати виконання

Усі три прогони відповідали критеріям: HTTP-помилок немає, p95 становить 52–55 мс. Зі збільшенням кількості потоків до 15 пропускна здатність зросла, а p95 не погіршився.

15 користувачів - найбільше досліджене навантаження цього сценарію. Для оцінки промислової місткості потрібні довші прогони, реалістичний think time, операції запису та окремий генератор навантаження.


## Висновок

Створено й виконано JMeter-план для трьох рівнів паралельності. У 1260 запитах помилок не зафіксовано; локальні критерії часу відповіді виконано. Збережені JTL дають змогу повторно перевірити обчислені метрики.
