## Мета роботи

## Завдання

Описати функціональність у форматі Given–When–Then, реалізувати step definitions, запустити сценарії й проаналізувати результати.


## Теоретичні відомості

BDD описує поведінку системи мовою предметної області. Given задає передумову, When - дію, Then - спостережуваний результат. Сценарій є конкретним прикладом вимоги, зрозумілим тестувальнику, розробнику та замовнику.

TDD зазвичай починається з перевірки малого програмного елемента і циклу red–green–refactor. BDD акцентує поведінку та спільну мову. Ці підходи можуть доповнювати один одного на різних рівнях.

Cucumber зіставляє текст кроків із методами Java. Hooks створюють і прибирають незалежний контекст, а assertions перевіряють бізнес-результат. Невизначений чи неоднозначний крок не повинен вважатися успіхом.


## Хід виконання

Додано cucumber-java та cucumber-junit 7.20.1. RunCucumberTest запускає .feature-файл і формує JSON/HTML-звіт. Step definitions розміщено в ua.edu.kntu.jobs.bdd.

Описано шість сценаріїв: пошук без залежності від регістру, відсутній збіг, включна зарплатна межа, успішний відгук, повторний відгук та закрита вакансія.

Кожен сценарій отримує окремий файл SQLite. Кроки створюють ролі, резюме й вакансію, виконують дію та порівнюють кількість або статус. Після сценарію repository закривається, тимчасові файли прибираються.


```text
mvn -B -ntp -Dtest=RunCucumberTest verify
```


```
Feature: Job search and application
  A seeker finds vacancies and sends one application with a saved resume.

  Scenario: Case insensitive search
    Given the catalog contains the demo vacancies
    When I search for "JAVA" in "Київ" with minimum salary 30000
    Then I receive 2 vacancies

  Scenario: No matching vacancy
    Given the catalog contains the demo vacancies
    When I search for "Rust" in "Київ" with minimum salary 0
    Then I receive 0 vacancies

  Scenario: Salary boundary is inclusive
    Given the catalog contains the demo vacancies
    When I search for "Java" in "Київ" with minimum salary 40000
    Then I receive 1 vacancies

  Scenario: Successful application
    Given a registered seeker with a saved resume
    And an active vacancy
    When the seeker applies once
    Then there is exactly 1 application

  Scenario: Repeated application is rejected
    Given a registered seeker with a saved resume
    And an active vacancy
    When the seeker applies twice
    Then the second application is rejected with status 409
    And there is exactly 1 application

  Scenario: Closed vacancy is unavailable
    Given a registered seeker with a saved resume
    And a closed vacancy
    When the seeker applies once
    Then the application is rejected with status 409
    And there is exactly 0 application

```


## Результати виконання

Cucumber виконав шість сценаріїв; усі пройшли. HTML-звіт показує 6 PASSED і 100% виконаних сценаріїв. Повторний відгук відхилено з 409, а в історії залишився один запис.

Сценарій закритої вакансії підтвердив 409 і нуль відгуків. Жоден сценарій не був skipped або undefined.


## Висновок

Створено виконувану специфікацію поведінки з шести Gherkin-сценаріїв. Step definitions пов’язали бізнес-умови зі справжнім сервісом і SQLite; усі сценарії успішні.
