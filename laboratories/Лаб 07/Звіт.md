## Завдання

## Теоретичні відомості

REST API надає ресурси через HTTP. GET читає дані, POST створює або виконує дію, PUT оновлює резюме, PATCH змінює окремий стан. Код 2xx позначає успіх, 4xx - відхилений запит клієнта, 5xx - серверну помилку.

Postman-колекція об’єднує запити й JavaScript-перевірки. Newman запускає таку саму колекцію з командного рядка. Змінні середовища відокремлюють адресу сервера від сценарію, cookie jar зберігає сесію між входом і наступними запитами.

Перевірка API має порівнювати не лише статус, а й форму JSON, конкретні значення та стан після дії. Наприклад, після logout захищений /api/me має знову повертати 401.


## Хід виконання

Створено postman/IPZ.postman_collection.json з базовою адресою локального сервера. Перед першим запитом генерується унікальний навчальний email; усі наступні запити цього прогону використовують його.

Колекція містить health, каталог, анонімний профіль, реєстрацію, вхід, власний профіль, відсутнє та створене резюме, відгук, повторний відгук, вихід і перевірку скасованої сесії.

Кожен запит має assertions статусу й JSON. Додатково перевіряються status=ok, відповідність count довжині списку та email поточного користувача. Колекцію реально виконано Newman; результати звірено з Python API-набором.

## Результати виконання

Newman виконав 12 запитів і 27 assertions без помилок. Очікувані негативні відповіді 401, 404 і 409 також пройшли: успіх тесту означає відповідність контракту, а не обов’язково статус 200.

Окремий Python-набір додатково перевірив 26 API-кейсів із ролями, валідацією й помилковими маршрутами. Знеособлений підсумок Newman збережено в evidence/newman-summary.json.
