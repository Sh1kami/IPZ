## Тема роботи

Тестування інтеграції


## Мета роботи

Перевірити взаємодію HTTP-рівня, бізнес-логіки та SQLite за допомогою інтеграційних тестів.


## Завдання

Підготувати ізольоване середовище, визначити сценарії взаємодії компонентів, написати інтеграційні перевірки, виконати їх і проаналізувати стан даних.


## Теоретичні відомості

Інтеграційний тест перевіряє межу між компонентами, де можливі помилки серіалізації, авторизації, транзакцій і збереження. Правильний результат окремої функції не гарантує правильність HTTP-відповіді або запису до БД.

Тимчасова SQLite забезпечує справжній SQL і обмеження унікальності. Для кожного тесту потрібні окремі дані. Динамічний порт усуває конфлікти, а завершення сервера й executor запобігає витоку ресурсів.

Перевірка повторного відкриття БД підтверджує збереження. Конкурентні запити потрібні для правил, які мають залишатися атомарними: наприклад, одночасний повторний відгук повинен створити лише один запис.


## Хід виконання

JobPortalServiceTest виконує 12 перевірок service → JDBC → SQLite. SQLiteHttpIntegrationTest має 13 перевірок client → HTTP → service → repository → SQLite. Загалом досліджено 25 інтеграційних JUnit-методів.

Через справжні HTTP-запити перевірено JSON, cookie, digest сесії, вихід, резюме, ролі, власність вакансій, пошук, неправильні тіла запитів і збереження даних. База не замінюється mock-об’єктом.

Два одночасні відгуки стартують через CountDownLatch. Очікувані результати - 201 і 409, а в БД має залишитися один відгук. Інший тест закриває й повторно відкриває той самий файл SQLite та перевіряє збережені сутності.

    @Rule public TemporaryFolder temp=new TemporaryFolder();

    private final Gson gson=new Gson();
    @Before public void before() throws Exception {db=temp.getRoot().toPath().resolve("http.sqlite");portal=new JobPortalServer(db).start(0);client=HttpClient.newHttpClient();}

    private record Response(int status,JsonObject body,HttpResponse<String> raw) {}
    private Response send(String method,String path,Object body,String cookie) throws Exception {
        return raw(method,path,body==null?null:gson.toJson(body),cookie,body==null?null:"application/json",null);
    }
    private Response raw(String method,String path,String body,String cookie,String type,String origin) throws Exception {
        var b=HttpRequest.newBuilder(URI.create(portal.baseUrl()+path));
        if(cookie!=null)b.header("Cookie",cookie);if(type!=null)b.header("Content-Type",type);if(origin!=null)b.header("Origin",origin);
        b.method(method,body==null?HttpRequest.BodyPublishers.noBody():HttpRequest.BodyPublishers.ofString(body,StandardCharsets.UTF_8));
        var r=client.send(b.build(),HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));return new Response(r.statusCode(),JsonParser.parseString(r.body()).getAsJsonObject(),r);
    }
    private long register(String email,String role) throws Exception {Response r=send("POST","/api/auth/register",Map.of("name","Навчальний користувач","email",email,"password","TestPass26!","role",role),null);assertEquals(201,r.status());return r.body().getAsJsonObject("user").get("id").getAsLong();}

## Результати виконання

Усі 25 інтеграційних методів пройшли. HTTP-клієнт отримав очікувані статуси й JSON; БД зберегла унікальність, власність даних та результати після повторного відкриття.

Для конкурентного відгуку отримано одну успішну вставку й одну керовану відмову. Невдале оновлення не пошкодило попереднє резюме.
