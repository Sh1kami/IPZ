## Тема роботи

Тестування юніт-тестами


## Мета роботи

Навчитися розробляти юніт-тести JUnit для нормальних, помилкових і граничних вхідних даних.


## Завдання

Виділити класи для ізольованих перевірок, написати тести з assertions і перевірками винятків, виконати набір та проаналізувати його результати.


## Теоретичні відомості

Юніт-тест перевіряє малу одиницю поведінки без HTTP та зовнішньої бази. Arrange готує дані, Act виконує дію, Assert порівнює результат. Незалежні очікування потрібно формувати з контракту, а не повторенням тієї самої реалізації.

Граничні значення часто виявляють помилки на одиницю. Для Unicode довжина у UTF-16 code units і кількість code points можуть відрізнятися. Валідація має рахувати саме визначену контрактом одиницю.

AssertThrows перевіряє керований виняток, assertEquals - точне значення, assertTrue/False - логічну умову. Для хешування важливі правильна перевірка пароля, випадкова salt і відмова для пошкодженого формату.


## Хід виконання

Виділено Validation, JobFilter і PasswordHasher. Вони не потребують HTTP-сервера чи SQLite. Для кожного правила підібрано звичайні дані, межі, некоректні значення та спеціальні символи.

ValidationTest містить 11 JUnit-методів: довжини тексту й пароля, null, порожні значення, email, ролі, id та зарплату. Вкладені набори даних перевіряють кілька значень у межах одного методу.

JobFilterTest має 11 методів для регістру, буквального пошуку, станів і AND-фільтрів. PasswordHasherTest містить 7 методів для PBKDF2, salt, digest та невалідних хешів. Разом виконано 29 юніт-тестів.

```
    @Test
    public void textBoundsCountUnicodeCodePointsAfterTrim() {
        Object[][] limits = {
            {"name", 2, 80}, {"resumeTitle", 5, 120}, {"resumeText", 20, 10000},
            {"resumeSkills", 0, 1000}, {"jobTitle", 5, 120}, {"company", 2, 120},
            {"city", 2, 80}, {"jobDescription", 20, 10000}, {"coverLetter", 0, 2000}
        };
        for (Object[] limit : limits) {
            String field = (String) limit[0];
            int min = (Integer) limit[1], max = (Integer) limit[2];
            String minimum = SUPPLEMENTARY.repeat(min), maximum = SUPPLEMENTARY.repeat(max);
            assertEquals(field + " lower boundary", minimum,
                    Validation.text(" \t" + minimum + "\r\n ", field, min, max));
            assertEquals(field + " upper boundary", maximum,
                    Validation.text("  " + maximum + "  ", field, min, max));
            if (min > 0) {
                validation(() -> Validation.text(SUPPLEMENTARY.repeat(min - 1), field, min, max));
            }
            validation(() -> Validation.text(SUPPLEMENTARY.repeat(max + 1), field, min, max));
        }
    }

    @Test
    public void requiredTextRejectsNullAndTrimmedBlank() {
        validation(() -> Validation.text(null, "name", 2, 80));
        validation(() -> Validation.text(" \t\r\n ", "name", 2, 80));
        assertEquals("", Validation.text(" \t\r\n ", "skills", 0, 1000));
    }
```


## Результати виконання

29 із 29 JUnit-тестів пройшли, failures/errors/skipped дорівнюють нулю. Перевірено включні межі, невалідні дані та Unicode supplementary symbols.

Перевірки хешування не порівнюють два незалежно згенеровані хеші на рівність: salt має відрізнятися, а перевірка одного правильного пароля повинна бути успішною для кожного з них.


## Висновок

Створено й виконано ізольовані JUnit-перевірки трьох доменних компонентів. Набір охоплює валідні дані, винятки, межі, Unicode і правила хешування без залежності від інтерфейсу та бази.
